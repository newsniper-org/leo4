# tests/conformance/reverse/

Phase 10-E2 (2026-05-21). Reverse-direction byte-parity
fixtures. Mirrors the structure of the forward-direction
conformance harness in `tests/conformance/` but exercises
the **reverse pipeline** (Lean calling Rust through the
worker dispatcher).

## Scope

The forward `tests/conformance/run.sh` checks that
Lean-side encoders and Rust-side decoders agree on the
canonical-ABI wire format for every primitive — emitting
fixture lines like `nat/0=01` from `gen.lean` and re-encoding
on the Rust side via `crates/leo4-abi/tests/cross_impl.rs`.

This subdirectory adds the **reverse-direction** variant:
the Rust-side `leo4-rust-worker` is the one encoding /
decoding values (because Rust is the *callee* in this
pipeline), and the Lean-side wrappers (generated by
`leo4-rust-emit --emit-lean`) marshal in the other
direction.

## What's in (Phase 10-E2 scope)

This commit ships the **skeleton**:

- `README.md` — this file, documenting the intended
  contract.
- A fixture-shape proposal, not yet a runnable harness.

The cross-impl conformance for the *canonical-ABI bytes
themselves* is already exercised by the forward harness
(`tests/conformance/run.sh`) and the in-process
`tests/mangling/run.sh`. Since both pipelines use the same
encoders / decoders from `leo4-abi`, the byte-parity
guarantee is transitive — what's NEW about a reverse
harness is the **wire envelope** (worker frames,
handshake, request/response framing).

## What's deferred to E2.x

- `tests/conformance/reverse/run.sh` — driver that spawns
  the worker, sends a synthetic request, reads back the
  response, and compares against a recorded byte sequence.
  Needs a stable per-fixture cdylib (use
  `examples/05-rust-export/` as the basis) and a way to
  pin the worker's stdout/stderr deterministically.
- `fixtures/*.bin` — recorded request + response frames,
  byte-pinned.
- `expected/*.txt` — human-readable diff target.

When implementing E2.x:

1. Write a one-shot fixture-recorder mode for the worker:
   `LEO4_WORKER_DUMP_FRAMES=/path/to/dump/dir` causes the
   worker to write every received-request + sent-response
   frame as `<seq>.req.bin` / `<seq>.resp.bin`.
2. The harness invokes the worker against a known cdylib
   with a known call sequence, captures the frames,
   diffs against `fixtures/`.
3. CI rotation: if the worker's wire format intentionally
   changes (e.g., a new frame kind from Phase 10-B1's
   callback ABI), the fixtures get regenerated and
   committed as part of the same PR that makes the wire
   change.
